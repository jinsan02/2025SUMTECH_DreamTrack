# DreamTrack — 4단계 LLM 진로 설계 파이프라인

24문항 설문 응답을 **진단 리포트 → 개인화 심층질문 → 14일 실행 로드맵 → 동기부여 퀴즈**로 순차 변환하는 진로 설계 파이프라인입니다.

> **2025 SUMTECH 해커톤 장려상** · 5인 팀 · 담당: AI 파이프라인 설계, 단계 간 데이터 계약, 프롬프트 설계

---

## 1. 무엇을 풀려고 했나

기존 진로 추천 서비스는 설문을 받아 직업 이름 하나를 돌려주고 끝난다. 학생 입장에서는 그 직업까지 가는 길이 비어 있어서 결과를 받아도 다음 행동이 정해지지 않는다.

DreamTrack은 **직업을 추천하는 대신 현재 상태와 목표 사이의 gap을 실행 가능한 단기 활동으로 바꾸는 것**을 목표로 했다. 그래서 한 번의 LLM 호출로 끝내지 않고, 앞 단계의 산출물이 다음 단계의 입력이 되는 4단계 체인으로 설계했다.

## 2. 파이프라인 구조

4개의 독립적인 LLM 호출 함수가 체인을 이루고, 각 단계는 **정해진 형식의 산출물**을 다음 단계에 넘긴다.

| Stage | AI 역할 | 입력 | 출력 | 핵심 임무 |
|---|---|---|---|---|
| **AI #1** | 종합 진단 분석가 | 24문항 설문 (JSON) | 8단계 분석 리포트 (Markdown) | 강점·목표·RIASEC·Gap 초안을 도출 |
| **AI #2** | 심층 면접관 | AI #1 리포트 (Markdown) | Gap 요약 + 개인화 심화질문 5개 (JSON) | 리포트의 가설을 학생의 선호·현실성으로 검증 |
| **AI #3** | 최종 로드맵 전략가 | AI #1 리포트 + AI #2 답변 | 14일 확정 로드맵 (JSON) | 학생의 최종 의사를 반영해 실행 계획 확정 |
| **AI #4** | 동기부여 튜터 | 최종 로드맵 (JSON) + 목표 분야 | 최신 트렌드 퀴즈 1문항 (JSON) | 로드맵 실행 동기 부여, 관심 분야 최신 정보 연결 |

**데이터 흐름**

```
설문 응답 (JSON)
      │  AI #1  generate_initial_report()
      ▼
진단 리포트 (Markdown)  ──────────────┐
      │  AI #2  generate_gap_and_questions()
      ▼                              │
심화질문 5개 (JSON) → 학생 답변       │
      │                              │
      ▼  AI #3  generate_final_roadmap()  ◀┘
14일 로드맵 (JSON)
      │  AI #4  generate_quiz()
      ▼
트렌드 퀴즈 (JSON)
```

정성적 정보(Markdown 리포트)를 정량적 실행 계획(JSON 로드맵)으로 넘기는 지점이 이 구조의 핵심이다. AI #2와 AI #4는 `response_format={"type": "json_object"}`로 출력 형식을 고정해, 다음 단계가 파싱에 실패하지 않도록 했다.

## 3. 설계에서 실제로 바꾼 것

프롬프트를 처음 쓴 뒤 출력이 의도와 어긋나는 지점이 세 군데 있었고, 각각 규칙을 명시해 고쳤다.

**AI #2 — 질문이 과제형으로 나오는 문제**
초기 프롬프트는 `ML 파이프라인을 제시해 보라` 같은 기술 과제형 질문을 만들어냈다. 고등학생이 답할 수 없는 질문이라 다음 단계 입력으로 쓸모가 없었다. 질문 유형을 **개인 검증형으로 한정**하도록 프롬프트를 재구성해, 현실적인 주당 투자 시간·학습 스타일 선호·영어 학습 장벽처럼 학생의 제약과 의지를 묻게 했다.

**AI #3 — 로드맵 기간이 길어지는 문제**
기간을 열어두면 모델이 3개월·6개월짜리 계획을 만들었다. 학생이 지치기 전에 성취를 경험하는 것이 목적이었으므로 `horizonDays: 14`로 기간을 고정했다.

**AI #3 — 활동 분류가 서비스와 맞지 않는 문제**
모델이 활동을 `skills` / `experience` 같은 일반 용어로 분류했는데, 이 값이 그대로 후속 UI의 분류 기준이 된다. 고등학생의 활동 영역에 맞춰 **교내 / 교외 / 자기계발 세 가지만** 사용하도록 프롬프트에서 강제했다.

**AI #4 — 퀴즈가 로드맵과 따로 노는 문제**
퀴즈만 단독으로 생성하면 로드맵과 연결되지 않았다. AI #3의 로드맵 활동을 퀴즈 해설(`explanation`)에 포함시켜, 학생의 작은 실행이 목표 분야의 최신 흐름과 어떻게 이어지는지 설명하도록 했다.

## 4. 설문 세트

`questionset.json`에 24문항이 들어 있다.

- **Q1–Q7** 리커트 5점 척도 — Holland RIASEC 6유형(R·I·A·S·E·C) 매핑용
- **Q8–Q17** 단일·복수 선택 — 흥미 과목, 관심 분야, 강점, 활동 경험, 정보 탐색 경로, 성향
- **Q18–Q24** 주관식 — 희망 진로와 그 이유, 주도적으로 한 활동, 어려움을 넘긴 경험

AI #1은 리커트 점수를 RIASEC에 매핑하고 선택·주관식 응답과 교차해 강점과 목표를 뽑는다.

## 5. 기술 스택

| 구분 | 내용 |
|---|---|
| LLM | OpenAI API · `gpt-5-nano-2025-08-07` (4단계 전부 동일 모델) |
| 언어 | Python 3.x |
| 의존성 | `openai`, `python-dotenv` |
| 환경 | Conda 가상환경, `.env`로 API 키 분리 |

의존성을 두 개로 묶은 것은 의도적이다. 해커톤 기간 안에 프레임워크 학습 비용을 쓰지 않고 파이프라인 구조 자체에 시간을 쓰기 위해서였다. 모델도 단계별로 바꾸지 않고 하나로 통일해, **프롬프트 복잡도가 결과를 얼마나 좌우하는지**를 모델 변수 없이 확인하려 했다.

## 6. 저장소 구성

```
main.py             4단계 파이프라인 구현과 데모 실행 블록
questionset.json    24문항 설문 세트
requirements.txt    openai, python-dotenv
.env.example        환경변수 템플릿 (실제 키는 커밋하지 않음)
```

## 7. 실행

```bash
git clone https://github.com/jinsan02/2025SUMTECH_DreamTrack.git
cd 2025SUMTECH_DreamTrack

conda create -n DreamTrack python=3.11
conda activate DreamTrack
pip install -r requirements.txt

cp .env.example .env      # OPENAI_API_KEY 값을 채운다
python main.py
```

`main.py`의 `__main__` 블록은 설문 응답과 심화질문 답변을 하드코딩한 **데모 시뮬레이션**이다. 실제 사용자 입력을 받는 UI는 이 저장소 범위 밖이다.

## 8. 한계와 확인하지 않은 범위

- **자동 테스트가 없다.** 각 단계의 출력은 해커톤 기간 중 눈으로 확인했고, 회귀 테스트나 출력 스키마 검증 코드는 작성하지 않았다.
- **정확도를 측정하지 않았다.** 진단 결과와 로드맵의 품질을 평가할 기준이나 정답셋이 없다. 이 저장소에는 성능 수치가 없으며, 있는 것처럼 인용해서는 안 된다.
- **AI #3의 웹 검색 통합은 프롬프트 지시 수준이다.** 로드맵 Task에 유사한 교내 프로그램·대회를 반영하도록 지시했지만, 실제 검색 API 연동은 구현하지 않았다.
- **단일 사용자 데모다.** 동시 요청, 재시도, 비용 제어, 로깅은 다루지 않았다.
- 1박 2일 해커톤 산출물이며, 이후 서비스로 운영한 이력은 없다.

## 9. 배운 것

한 번의 프롬프트로 좋은 답을 받는 것보다, **단계 사이에 무엇을 넘길지 형식으로 못 박는 일**이 결과를 좌우했다. AI #2의 출력 형식이 흔들리면 AI #3이 파싱에 실패하고, AI #3의 카테고리가 자유롭게 나오면 서비스 UI가 분류를 못 한다. 각 단계의 산출물을 다음 단계의 입력 계약으로 보고 형식과 값의 범위를 먼저 고정한 뒤에야 체인이 안정적으로 돌았다.
